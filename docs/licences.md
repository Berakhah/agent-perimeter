(table above). `uvx pip-licenses` alone reports on `pip-licenses`'s own
isolated environment, not this project's — `uv run --with pip-licenses` was
used instead so the table reflects `agent-perimeter`'s real resolved
dependency set, dev group included. `pip-licenses` is not itself a project
dependency (pyproject.toml has no such entry) and is invoked ad hoc, per
task 17 ruling 5.

**No AGPL, SSPL, BUSL or non-commercial-licensed dependency was found**, on
either the Python side (table above) or the web/npm side (`cd web && npx
license-checker --summary`, 393 packages, full breakdown below).

| `@img/sharp-win32-x64` 0.35.4 | Apache-2.0 AND LGPL-3.0-or-later | npm (transitive, optional peer of `next`) | runtime-reachable if `next/image` server-side optimization is exercised; this UI does not currently use `next/image` |

`hypothesis` and `@axe-core/playwright` were already known and flagged in an
earlier task; both are confirmed dev-only and non-AGPL here again, not a new
surprise. `certifi`, `pathspec`, `psycopg`/`psycopg-binary`,
`lightningcss`/`lightningcss-win32-x64-msvc` and `@img/sharp-win32-x64` are
new findings from this task's audit, none of them AGPL/SSPL/BUSL/non-commercial:

- **MPL-2.0** (`certifi`, `pathspec`, `@axe-core/playwright`/`axe-core`,
  `lightningcss`/`lightningcss-win32-x64-msvc`) is file-level weak copyleft:
  it requires that modifications *to the MPL-covered files themselves* stay
  MPL-licensed if redistributed, and explicitly permits combining with a
  larger work under a different licence (this project's own Apache-2.0 code
  included) with no obligation on the larger work. None of these packages'
  source is modified here.
- **LGPL-3.0** (`psycopg`/`psycopg-binary`, and the LGPL half of
  `@img/sharp-win32-x64`'s dual licence) permits linking/dynamic use from a
  differently-licensed application without relicensing the application —
  the obligation triggers only on modifying and redistributing the LGPL
  library itself, which this project does not do; both are pulled in
  unmodified via PyPI/npm.
- `certifi` and `psycopg`/`psycopg-binary` are the two genuinely
  **runtime**, not dev-only, entries in this list (`certifi` transitively
  via `httpx`, `psycopg` directly). Both are extremely common, effectively
  unavoidable choices in their category (a Python HTTPS client's CA bundle;
  the canonical async-capable Postgres driver) and neither is AGPL, SSPL,
  BUSL or non-commercial, so per this project's own "Apache/MIT/BSD deps
  only — flag any AGPL dependency explicitly" rule (CLAUDE.md), they are
  flagged here rather than adopted silently, but are not blocking findings.
